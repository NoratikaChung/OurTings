# OurTings — handoff context

Read README.md first (features, setup, commands). This file records decisions and status.

## Decisions
- PWA (user wrote "RWA"): Vite + React 19 + TS, `vite-plugin-pwa` autoUpdate. Single page, no router (no SPA rewrite needed).
- Backend: Firebase Firestore (Spark/free), chosen over Supabase (pauses idle free projects) and Neon (no realtime, needs API code). Whole `events` collection is subscribed; fine for two people's data.
- Access: user wanted no login. Compromise approved by user: one shared Firebase email/password account (`ourtings@noratikachung.com`); its password is the "secret code", entered once per device. `firestore.rules` admit only that email (any other signed-up account is rejected). The Nora/Anant choice is local only (`localStorage`), used for event ownership, comments and filters.
- Times: timed events store wall-clock `yyyy-MM-ddTHH:mm` + `timeZone` (IANA zone of the device that saved them); `occurrencesBetween` builds them as `TZDate`s (`@date-fns/tz`) so each device shows them in its own zone and repeats keep their clock time in the entry zone across DST. All-day events and birthdays have `timeZone: ''` (dates are the same everywhere). Events saved before zones existed have no `timeZone` and read as the device's local time. The editor edits timed events in device time and saves with the device's zone. Clock times use `Intl` (`lib/format.ts`) so they follow the phone's 12/24-hour style.
- Repeats: `repeat` none/daily/weekly/monthly/yearly + `repeatUntil` (inclusive date, '' = forever), expanded only inside the visible range (no stored instances; the calendar has no min/max date). Steps are taken from the first date each time (31st → last day of shorter months, no drift). Birthdays repeat yearly via the same code; 29 Feb → 28 Feb in non-leap years. Editing/deleting a repeating event changes the whole series. All-day events span whole days through their end date. Week starts Monday (`WEEK_STARTS_ON`).
- Event owner = creator (whose calendar it's on). Anyone may edit/delete/comment. Cards show the newest 2 comments as squarish speech bubbles "[icon] Name: text…" (names Nora red, Anant blue: `--nora-name`/`--anant-name`), from one `collectionGroup('comments')` listener (rules allow reads on `/{path=**}/comments`). Each card measures (ResizeObserver) whether its bubbles fit; if not (short or narrow timetable slots) they stay laid out but hidden and the latest commenter's icon with a count badge shows in the top-right corner. The event sheet shows the thread chat-style (own comments on the right). Week/day timetable keeps all 24 hours (one real 1px line per hour) and opens scrolled to 6 am (`OPEN_AT_HOUR`).
- Timetable time picking (`Timetable.tsx`, user asked for Outlook-like): snaps to 30-min slots; a released single-slot pick becomes 1 h. Mouse: click selects a slot (highlight with times), double click creates 1 h, drag (pointer capture) creates the dragged block on release. Touch (a plain drag must scroll): tap selects a slot; pressing the selection starts picking at once, so tapping it creates (a double tap of any speed works) and dragging from it stretches it; a 400 ms long press on any empty slot also starts picking (`navigator.vibrate` buzz on Android). This replaced a 350 ms double-tap window + long-press-only dragging after the user reported double click and drag not working; probable cause (inferred, not reproduced with the user's setup): touch input such as Chrome's device mode, where a normal 500 ms Windows double-click missed the window and a plain drag scrolls. While picking, a non-passive `touchmove` preventDefault stops the scroll; native `dblclick` is ignored after touch. Columns use `touch-action: manipulation` (no double-tap zoom) and no text selection/callout. A pick's pointerup stops propagation so it isn't read as a week swipe. Editor target carries the picked `end`. Checked with Playwright (laptop dblclick + drag, iPhone WebKit 450 ms double tap, Galaxy Tab CDP touch long-press drag and tap-then-drag). User menu (log out) closes on any outside press (capture-phase listener; cards stop bubbling) or Esc.
- Live updates come from Firestore `onSnapshot` listeners (server push over one connection), not polling. The app always opens on the month view at today, and returns there when resumed on a later day. The installed PWA calls `registration.update()` on every return to the foreground (`main.tsx`), because iOS/Android resume the app without a page load, which is the only time browsers otherwise look for a new service worker.
- Fixed header (user request): `.app:has(> .calendar)` is exactly 100dvh and `.calendar`/`.view` are flex columns, so the topbar and toolbar never scroll; the timetable, the month agenda and the year view scroll inside. The month agenda (`.agenda`) is as tall as its events until it reaches the screen bottom, then scrolls (min 120px; on screens too short for grid + agenda the whole month view scrolls). Month day double click (mouse `dblclick`) or double tap (touch, two `pointerup`s on the same day < 500 ms; `dblclick` isn't reliable on touch) opens the day view.
- Swipe (touch, all four views): finger right→left = next, left→right = previous (`.view` pointerdown/pointerup in `CalendarScreen.tsx`, > 60 px across, < 40 px down). Needs `touch-action: pan-y pinch-zoom` on `.view` and every element in it (`styles.css`): with the default `auto` the browser claims every drag as a possible scroll and sends `pointercancel`, so no swipe ever registered (measured in Chromium, both directions; the user saw only "previous" working on iPhone). Set on all descendants because the inner scroll areas would otherwise allow sideways pans again. Not `auto`, so double taps don't zoom (replaces the old `manipulation` on `.day-cell`/`.tt-col`). Regression test `tests/e2e/swipe.spec.ts` (Chromium only: touch drags go through CDP; also checks a vertical drag still scrolls the timetable).
- Device prefs (`localStorage`): `ourtings:user`, `ourtings:theme`, `ourtings:prefs:<user>` = { visible } (older stored prefs may still carry an unused `view`).
- Art: original SVG in `src/art/` for the dark Scenery, WelcomeScene scenery, DialogOrnament and the dark avatars' cavern frame (halo, ring, sparkles) + drawn cloaks (Hornet's is a slim bell, user-requested). User-supplied pictures (originals in `assets/`): welcome Hornet/Knight (`src/art/welcome/`, trimmed + mirrored to face each other); avatars (`src/art/avatar/`: Hornet/Knight mask icons trimmed and laid over the drawn cloaks, Totoro badge cut to its ring, white elf icon; light avatars are the pictures clipped to a circle); light scenery (`src/art/ghibli/`: 720×405 Howl's valley background fitted to the screen height; `--focus` keeps 40% of the picture in view (castle) on tablets/laptops and 85% (snowy mountain + sheep) on screens ≤600px wide, user-requested; blurred copy fills the sides on screens wider than 16:9; CSS mist puffs in % of the picture over its hills, the castle's feet and the sheep's hill; big soft CSS clouds cross the sky every ~3 min, two behind Totoro and two in front of him; Totoro is min(max(33.3vw, 33.3vh), 416px) (about a third of an iPhone's height), scaled 0.75× at the top of his path to 1.15× at the bottom (depth, user-requested; each `scenery-fly` keyframe's scale matches its height), colours softened + slight blur + sky-tinted shadow via CSS filter to blend with the painting, flies a 150 s loop; original SVG grass foreground in the picture's meadow greens, fading in from the top, swaying tufts in two layers, plus 5 sparse pampas reeds that bend in the wind; white elf (brightened + soft glow via CSS filter) walks between the grass layers on a 90 s loop, flipping for the walk back). App icon = user's transparent bunny (`assets/icons/app-icon-bunny.png`) → `public/icon.png` (square, transparent) → `npm run icons`: black background for apple-touch and maskable (iOS can't show transparency; it would render black anyway), transparent for browser/desktop icons. Light theme = Studio Ghibli style (Nora = white elf, Anant = Totoro). Dark theme = Hollow Knight style (Nora = Hornet, Anant = Knight) and is the first-open default.
- CI mirrors `pdf-tools`: GitHub Actions verify; Vercel native Git integration deploys (immediately on push, in parallel with Actions; it does not wait for them). Firestore rules are deployed manually (README step 1.5).
- Repo is private. Vercel Hobby only deploys private-repo commits whose author is the project owner, so this repo's local git config authors commits as `Noratika Chung <101931866+NoratikaChung@users.noreply.github.com>`. Commits authored with the work email (`noratika.chung@k3capitalgroup.com`, linked to GitHub account NoratikaChungK3) are blocked ("Deployment was blocked").
- Firestore emulator port is 8085 (8080 is used by WSL relay on the dev machine).
- Welcome (`src/components/Welcome.tsx`, art in `src/art/WelcomeScene.tsx`): shown on every browser-tab visit, never when installed (`isInstalled()` = display-mode standalone or `navigator.standalone`). Butterfly tap calls `requestInstall()` (saved `beforeinstallprompt`, Chromium only) and reveals page 2 with per-device steps from `platform` in `src/lib/install.ts` (iOS has no install API; iPhone: ··· → Share → View More → Add to Home Screen; menu names checked against Apple/Google/Microsoft help pages, Oct 2026). Script wording is the user's ("Little ghost… a light flutters before you. Touch it." / "A gift, bound for your shell. Carry it home by clicking on your browser:" / "After you are done, seek this bunny on your home screen. Open it, and enjoy."; desktop/Android say "among your apps"). One typing clock reveals it top to bottom: intro, each step, the bunny icon, then the outro. The bunny sits beside the outro (not above it) so the longer script stays clear of Hornet's whisper on a 430×739 iPhone (24 px gap, measured); on short landscape screens (Galaxy Tab landscape 712 px tall, 1366×650 laptop) the box still touches/overlaps the whisper (-1 / -32 px, was -7 / -38 before this script change). Hornet whispers only a hint, never the code (the page is public). Tiny × = skip to the app. Knight height 0.92 units vs Hornet 1.45 (user-tuned).
